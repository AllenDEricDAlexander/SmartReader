# SmartReader

SmartReader 是一款本地优先的桌面科研文献阅读器，基于 Tauri、React、TypeScript 和 SQLite。它将 PDF 阅读、文献索引、论文信息维护、分类、批注与可配置的 AI 助手连接在同一份本地文献库中。

## 当前能力

### 文献导入与阅读

- 支持桌面原生文件选择、多选导入、目录导入、拖拽和系统 Open With。目录导入递归查找 PDF，不跟随符号链接；单份导入 PDF 上限为 128 MiB。
- 新导入文献保存为库内受管 PDF，按内容 SHA-256 去重；相同内容换文件名导入也只保留一份副本。
- 导入后通过 TypeScript 和 PDF.js 提取逐页文本并建立本地倒排索引。跨文献检索支持拉丁文字、中文、元数据、页码及上下文，结果可直接打开命中页。
- 保留单篇 PDF 内的全文搜索、真实匹配数量、页码跳转、缩放、适合宽度和页面、阅读历史前进/后退、最近文件及会话恢复。
- 支持真实的双 PDF 左右并排对比，两侧独立选择文献、定位和缩放，已有批注以只读方式展示；锁定文献会清除对应窗格。
- PDF 加载失败、超时、需要密码或索引失败均有明确状态；索引失败保留已导入文件，可输入原 PDF 密码后重试。没有文本层的扫描件不会被标记为已完成全文识别。
- 书签、选区高亮、下划线、锚定原文的笔记和页面笔记由 SmartReader 管理。支持跳转、编辑、删除、标签关联及批注 JSON 导入/导出，不写回原始 PDF。
- 在文献库可单篇或多选导出笔记 PDF；“笔记管理”还可同时选择库内文献和旧版按路径保存的文档记录。PDF 按文献和原文页码整理笔记、摘录、高亮、划线、颜色、标签、更新时间、选区位置及书签备注，无内容的文献也会标明。结果是独立的笔记汇总，不包含原 PDF 页面。中文等文字可搜索和复制；字体未覆盖的字符以图像显示，其相邻的受支持文字仍可选中。
- 为保证常见 PDF 阅读器正确显示中文，每份笔记 PDF 完整嵌入离线中文字体，文件会增加约 6 MB。
- 保留收藏、标签管理、快捷键覆盖与冲突提示、缓存状态、桌面集成及会话恢复偏好。
- 最近文件、收藏文件和文献库使用统一的文献表格，展示可用的作者、期刊、路径、最近打开时间、阅读进度、页码和标签；旧路径记录缺少的信息显示为空，库内文献显示“本地文献库”。首页最近阅读保留列表与卡片切换及其保存的视图偏好。
- 完整表格默认每页 10 条，可选择每页 20 或 50 条；表头选择当前页，也可选择全部筛选结果，批量操作会提示不在当前显示范围的选中项。收藏文件支持批量取消收藏，部分失败时保留失败项并提示重试。
- 设置以独立标签页打开，在首页、文献与设置之间切换时保留未保存的草稿；外部更新会合并到未编辑的设置项，关闭设置标签则放弃尚未保存的修改。可用 `Ctrl+Tab` 和 `Ctrl+Shift+Tab` 在文献与设置标签之间切换。

### 论文信息与预览

- 预览展示标题、作者、期刊、发表年份、DOI、摘要、关键词、研究主题、收录状态，以及研究领域、学科方向、期刊类型、文件大小、收藏和全部个人批注。
- 支持读取 PDF Info、XMP 和 PDF.js `info.Custom` 中明确的学术字段，包括 DOI、Journal、PublicationYear、PublicationDate。发表年份不会由文件创建时间猜测，未知收录状态不会由 AI 编造。
- 信息不全的学位论文、预印本等可手工补充。只将实际修改过的字段设为人工维护，重新索引和 AI 补全均保留这些值。
- 预览位于列表旁的独立区域，鼠标悬停可切换，支持固定、关闭及重新打开。较窄的桌面窗口使用分类选择器和上下布局，避免覆盖文献列表。
- 显式展开信息项会记录关注频率，用于优先排列个人常看的字段。实际前台阅读时间与按文本长度估算的阅读时长分别展示。

### 分类与批量管理

- 按研究领域、学科方向、发表年份、期刊类型、论文主题五个维度，使用提取或 AI 补全得到的信息自动归类。
- 支持创建、重命名、移动、合并和删除分类，以及最多 8 层的子分类。人工整理的分类和关联会被保留。
- 支持论文批量移动分类、追加归类、移出分类、置顶、收藏及删除。同一论文可归入多个分类，无需复制 PDF。
- 删除或合并分类保留论文。删除文献时会明确确认：删除库内副本、索引、批注与书签，不删除磁盘上的原始 PDF。
- 分类文件夹支持密码加密、锁定、解锁和解除加密，具体保护范围见下方“数据和加密边界”。

### 多厂商 AI

在“设置 → AI 厂商”中添加厂商名称、Base URL、模型名称和自己的 API Key，再选择当前厂商。客户端使用 OpenAI-compatible `POST /chat/completions` 协议，保留自定义路径前缀；通常填写厂商提供的含 `/v1` 的 Base URL，也接受完整的 `/chat/completions` 地址，不会重复追加路径。只填写主机（如 `https://api.example.com`）时按这些服务的惯例补 `/v1`，避免静默 404。

- 支持保存多套厂商配置，每个厂商可在“其他可选模型”中按行预先添加多个聊天模型，共用该厂商的地址和密钥。AI 问答页的厂商和模型按会话分别保存，切换会话或重启后自动恢复；同一厂商下的不同会话也可以使用不同模型。新会话继承当前选择，之后独立修改。支持 HTTP/HTTPS 地址，模型名称由用户填写。
- 厂商地址、API Key 和模型清单仍共用厂商配置，会话只保存自己的选择。旧会话尚未保存独立选择时，首次升级按当时的当前配置初始化一次，已有记录和上下文保留。厂商或模型被移除后，相关会话保留原选择并提示重新选择，历史不会被清空。设置页的“设为当前厂商”也只改变当前会话的选择。
- API Key 有三种保存方式，默认“仅本次会话”，重启后需重新输入：
  - “在本机记住”把密钥明文写入本机文献库文件，重启后自动可用；能读取该文件的程序即可读到，共用电脑不建议使用。
  - “加密保存”用至少 8 个字符的密码加密，重启后输入该密码解锁。
  - 下拉框只决定本次输入的新密钥如何保存，留空提交则沿用当前方式；“忘记密钥”同时清除会话、本机和加密保存的副本。
  改变聊天或 embedding 服务地址会清除旧凭据，避免将其带到新的地址。
- 文件导入、本地索引和阅读无需 AI。用户可手动补全文献信息，也可显式启用“导入后自动 AI 补全与分类”。
- 问答页面支持多个独立的多轮会话：提问与回答按顺序留在各自的会话中，追问仅携带当前会话的历史（按轮数和字符数截断最早的内容）。“新建对话”创建新的空会话，已有记录继续保留在历史列表。回答逐字流式输出，可随时取消；取消的那一轮不会在对话里留下残缺回答。推理模型的思考内容单独折叠显示，不计入回答正文。
- 流式回答仅在页面接近底部时自动跟随，向上阅读会暂停跟随；页头提供“回到最新回答”、生成中的“取消回答”和完成后的“继续提问”，后者直接定位原输入框并保留草稿。
- 所有会话自动保存在本机 SQLite 文献库中，每个会话分别保存所选厂商和模型、已完成的问答、来源、回答的厂商与模型标记、未发送草稿、回答模式及文献范围。历史列表优先展示置顶会话，默认以首条问题作为标题，可通过每条会话的重命名按钮保存自己的名称（1–100 个字符）；更名保留原聊天、上下文、草稿与厂商／模型选择，重启后继续使用该名称。点击历史可恢复该会话并继续追问。删除需确认，只移除指定会话；删除当前会话会打开另一条历史，最后一条删除后自动创建空会话。已有单会话本地记录自动迁移为一条历史，无需重新导入。
- 每条会话可独立置顶或取消置顶，最多置顶 10 个，数量按全部历史计算，包括搜索未显示和已锁定的会话。置顶会话可通过左侧手柄拖拽排序，也可聚焦手柄后用上下方向键调整；顺序自动保存在本机，重启后恢复，继续聊天或重命名不会改变已设置的顺序。旧数据首次使用仍保留原显示顺序，新置顶或再次置顶的会话追加到置顶组末尾，取消置顶或删除会话会保留其余置顶会话的相对顺序并释放名额。普通会话仍按更新时间从新到旧展示，新会话默认不置顶。置顶与排序操作不改变聊天时间、聊天内容、上下文或各会话的厂商／模型选择。
- 搜索结果中的置顶会话沿用已保存的顺序，也可在结果中拖拽调整；移动以完整置顶列表为准，未显示的会话仍保留，不会被遗漏或取消置顶。取消拖拽不会保存，保存失败会显示错误并保留原顺序，可以重新拖拽重试。
- 历史会话支持分组管理：可新建、重命名和删除分组，通过每条会话下方的分组选择框移动归属，分组名称与会话归属自动保存在本机，重启后保留。分组名称为 1–100 个字符，同名分组不可重复创建。旧会话默认“未分组”，可查看全部会话、未分组或指定分组，并在当前分组内搜索；在指定分组中新建对话会直接归入该分组。
- 有两个及以上自建分组时，可展开“调整分组顺序”，拖动分组左侧手柄排序，也可聚焦手柄后用上下方向键调整。顺序自动保存在本机，重启后恢复，分组筛选和会话归属选择框沿用同一顺序；“全部会话”“未分组”保持固定。新分组追加到末尾，重命名不改变顺序，删除分组保留其余分组的相对顺序。排序不改变当前分组、会话归属、聊天记录、上下文、草稿、厂商／模型选择或置顶顺序；取消拖拽或保存失败保留原顺序，可重新操作。
- 每个自建分组可通过名称左侧的箭头独立折叠或展开，状态自动保存在本机，重启后保留；旧分组和新分组默认展开。折叠隐藏历史列表中该分组的会话，计数、归属、聊天记录、上下文和置顶状态继续保留，当前聊天仍可继续。搜索可以查到已折叠分组中的会话，清空搜索后恢复折叠视图，搜索和切换会话不会改写折叠设置。重命名、排序和移动会话保留分组的折叠状态，保存失败保留原状态并支持重试。
- 删除分组需要确认，只删除分组本身，其中的会话全部回到“未分组”，聊天记录、上下文、草稿、文献范围、厂商／模型选择及置顶顺序继续保留。分组切换只筛选历史列表，移动当前会话到其他分组后仍可继续聊天。置顶数量与顺序按全部会话统一计算，筛选分组不会增加置顶名额或删除隐藏的置顶会话；加密会话可直接移动分组，内容仍需解锁相关文件夹后访问。
- 历史列表支持按标题或已完成的问答正文搜索，中英文均可匹配，英文不区分大小写；搜索只在本机运行，不修改会话或发送给 AI 厂商。清空搜索可恢复完整列表，点击匹配会话后仍可继续追问。未发送草稿不参与搜索。
- 关闭窗口或退出应用前等待待保存内容写完，重启后恢复上次打开的会话和完整历史列表；未完成的流式回答及对应问题不进入保存记录。新建或切换前先保存当前内容，保存或恢复失败会显示错误，不以空对话覆盖未能读取的记录。
- 打开来源 PDF、切到其他页面后返回或切换厂商/聊天模型，均保留当前对话和上下文。下一次请求使用新选择的厂商与模型，并携带当前会话、文献范围及回答模式下的历史问答；上下文仍按既有轮数和字符数上限裁剪，完整聊天记录保留在本地。不同会话、文献范围或回答模式的历史不会混入下一次请求。回答生成、添加文件、构建索引或保存切换期间，相关切换操作暂不可用。
- 涉及加密文献的会话（包括自定义名称）分别使用相关文件夹密钥加密保存，未解锁的历史隐藏名称和正文，显示加密与置顶标记及更新时间，可以置顶、取消置顶或删除，不参与正文或名称搜索，也不能重命名；解锁所有涉及的文件夹后可恢复、重命名和搜索，无需逐条打开。搜索不创建额外的明文索引，也可以直接新建其他会话或删除加密历史。显式锁定、删除文献、改变文献加密状态或忘记当前密钥仍按原有访问保护规则处理相关内容，不清空其他无关会话。API Key 继续遵循用户选择的保存方式；仅本次会话使用的密钥需在重启后重新输入，加密保存的密钥需解锁。
- 回答方式有两种：“检索本地文献并附来源”走 RAG 并给出来源标签与页码跳转；“直接与模型对话”不检索本地文献、不附来源。知识库没有可检索文件时自动使用后者并明确标注“未检索文献”，因此配置好密钥即可开始对话，不必先导入 PDF。明确指定了文件却都不可访问时报错，不会悄悄改成无依据回答。
- 问答页面可直接“添加本地 PDF”，按文件名筛选，并选择全部可检索文献或多份指定文件；选择为空时不会扩大到全库。
- 模型返回了来源里不存在的引用标签时，只移除该标签并说明，不再丢弃整条回答。
- AI 失败不会删除本地文件或索引。支持重试、取消、超时和明确的鉴权/权限/限额错误；不会将服务端原始错误或密钥写入对话里的错误提示（服务端原文可能回显论文摘录）。厂商自己的报错只在“验证连接”和“验证向量模型”里显示，这两个请求不含文献内容。聊天超时上限为 120 秒。服务以请求错误（400/404/405/406/422/501）拒绝流式、或对流式请求返回非事件流响应时，自动改用一次非流式请求；网络、鉴权和限额错误直接上报，不重复计费。

真实厂商的模型效果、账号权限和额度需要用户配置有效凭据后验证。仓库提供本地兼容接口用于功能复测，不附带真实厂商凭据。

### 知识库与语义检索

在 AI 厂商配置中填写独立的“Embedding 模型”。已有阿里云配置的编辑表单建议 `text-embedding-v4`，需保存后生效；点击“验证向量模型”可检查模型权限和返回维度。默认复用聊天地址与 API Key，也可填写独立的“Embedding Base URL”（接受完整 `/embeddings` 地址）。专用聊天部署可能没有 embedding 接口，此时需填写账号实际可用的 embedding 服务地址，并重新输入密钥。未配置 embedding 时保留已有全文检索，并在问答页面明确显示当前方式。

- 本地模式把公开文献向量持久保存在 SQLite，检索时只把问题向量和文献范围传入原生层，排序在 Rust 内按余弦相似度完成，向量不再逐次序列化进出界面；无需额外 Python 或数据库服务。文献按页分块，内容、模型或地址变化后重新生成向量；可手动重建或取消构建。解锁的加密文献向量只存在于当前会话内存，随问题一起传入该次检索。
- 云端模式使用 Milvus REST v2，需配置自己的服务地址和仅在当前会话保存的访问令牌。向量写入按维度命名的持久集合 `smartreader_knowledge_<维度>`，每份文献带 `paper_id` 与内容/模型指纹；重复提问和重启后通过强一致计数核对完整分块，复用完整索引，上传中断则重新建立。检索同时限制所选文件及当前指纹。文献内容变化时按 `paper_id` 替换该文献的行，加密、锁定或删除文献时尽力从所有受管维度集合删除该文献的向量；不会丢弃集合或删除其他文献。服务需允许列举、创建、描述、加载集合，以及插入、查询、检索和删除实体。只上传向量、分块 ID 与指纹，不上传原文；加密文献不进入云端。此模式不是文献云同步。
- 切回本地模式后，当前会话保留的 Milvus 令牌仍用于清理之前上传的向量。没有令牌或远端清理失败时，问答页显示明确提示；离线删除、退出应用后或更换云端服务后，旧服务中可能仍有向量，需要在对应 Milvus 服务中核对清理。本地加密和索引清理不依赖远端可用性。
- 配置 embedding 后，问答先向量检索，再把匹配摘录交给聊天模型；语义检索失败或没有相关段落时显示错误，不退回首页摘录来生成回答。
- “本地”指向量保存和检索的位置。复用阿里云 embedding 时，分块文本与问题仍发送至阿里云；生成回答时相关摘录和文献信息也发送至聊天厂商。加密文献仅在解锁会话内保留向量，不进入持久化向量缓存或 Milvus；本地模式下用户问答仍会调用所配置的 embedding 和聊天服务。

单份文献上限为 20,000 个分块及 8,388,608 个向量值；一次检索范围上限为 67,108,864 个向量值。超过容量时请缩小文件范围。embedding 按批请求，厂商拒绝某个批量大小时自动改用更小的批量。暂不支持扫描件 OCR。

## 数据和加密边界

- SQLite 位于 Tauri 应用数据目录下的 `smartreader.sqlite3`。库内文献状态和 PDF BLOB 通过原生二进制 IPC 传输，并由 Rust 命令在同一事务内提交，并检查 revision，冲突时不静默覆盖新数据。
- 既有 `desktop:` 路径记录保持原身份；从最近文件、书签等入口重开时继续使用原书签、批注与阅读位置，不强制迁移成新的受管文献。
- 受管文献的批注、收藏、阅读状态等写入同一文献记录。加密后不会另在旧文档表中保存一份库内批注明文。
- 文件夹加密使用 Web Crypto 的 PBKDF2-SHA-256 和 AES-256-GCM，保护库内 PDF、论文元数据、全文索引、阅读状态、批注和书签；不是对整个 SQLite 数据库进行加密。
- 加密文献解锁后才能导出笔记。导出前会等待已提交的笔记、书签和标签操作；导出文件未加密，且只能创建不存在的新文件，不会覆盖现有文件。生成或写入期间请求锁定会立即隐藏受保护文献，并取消和清理未完成的输出；如果清理失败，界面会提示文件路径。已完成的导出文件不会随文献锁定或删除而移除。
- 手工分类名称、目录结构、厂商地址/模型等外层配置仍可见，磁盘原始 PDF 不会被修改或加密。加密时保留手工分类与保险库归属，移除加密范围外的自动推断分类关联，并清理无引用的自动分类。
- 同一论文从所有分类入口共用加密状态。锁定会关闭相关标签页、撤销 Blob URL、清除相应字节缓存和界面内容，并丢弃迟到的读取、索引或 AI 结果。解锁密钥仅在当前会话保留。
- 文献加密或删除时，同一 SQLite 事务清除对应公开向量缓存；私有向量仅驻留解锁会话，锁定后清除。
- 一篇文献不能同时加入两个独立加密文件夹。加密目录的移动、合并或删除，以及将文献移出原加密范围，需要先解除相应加密；不会静默把文件降为明文。
- `LibraryStorage` 仅预留可替换的存储接口、稳定文献 ID 和 revision 边界。当前未实现云同步、浏览器持久化或移动端界面。
- 当前不包含 OCR、PDF 内容编辑/写回、文本或图片导出和打印。批注 JSON 导出与笔记 PDF 导出均不修改原始 PDF。

## 技术栈与结构

- Bun、Vite、React 18、TypeScript、Vitest。
- Tauri v2、Rust、rusqlite/SQLite；桌面 AI HTTP 传输使用 reqwest/Tokio，流式回答通过 Tauri Channel 转发原始响应文本，SSE 分帧在前端解析。
- `@react-pdf-viewer` 与 PDF.js 负责 PDF 阅读渲染；TypeScript 负责文献模型、索引、分类、加密和 AI 业务。

## 开发环境

需要 Bun、Rust toolchain 和 Tauri v2 所需系统依赖。

```bash
bun install
```

`postinstall` 会把 `pdfjs-dist` 的 worker、CMap 和标准字体复制到 `public/`，索引与阅读器均使用这些本地资源，支持离线读取采用标准中文字符映射的 PDF。已有依赖目录的工作区更新后，可运行 `bun run postinstall` 补齐资源再构建。

`bun install` 还会应用 `patches/@react-pdf-viewer%2Fcore@3.12.0.patch`：围绕当前可见页，动态预渲染前后各 20 页的实际画布和文字层，最多同时处理 3 页，优先可见区域和滚动方向前方。单页渲染较慢时，其余任务仍可继续准备窗口内的页面；已完成的页面进入视口时直接复用。快速滚动时，新可见页可抢占优先级最低的离屏任务；失效画布和文字层任务会取消，迟到的解析结果不会再启动渲染。补丁让开发和正式构建共用修复后的队列，正式产物仍由 Vite 压缩。升级 Viewer 时需重新核对补丁并运行 `src/viewer/pageRenderQueue.test.tsx`，其中覆盖真实页面组件的离屏渲染、并发上限、滚动复用、连续快速滚动和跳页。

```bash
# 前端开发服务器（仅开发壳，不提供浏览器端本地文献库）
bun run dev

# Tauri 桌面开发模式
bun run tauri

# TypeScript 类型检查
bun run typecheck

# 前端测试
bun run test

# 前端构建
bun run build

# Rust 格式检查
cargo fmt --manifest-path src-tauri/Cargo.toml --check

# Rust 测试
cargo test --manifest-path src-tauri/Cargo.toml
```

桌面原生存储和 AI HTTP 调用应通过 `bun run tauri` 验证。仅打开 Vite 页面不等同于完成桌面功能验证。

## macOS 本机打包安装

确认已经执行过 `bun install`，然后运行：

```bash
./scripts/build-install-macos.sh
```

脚本会构建 macOS `.app`，应用仅供本机使用的临时签名，安装或更新 `/Applications/SmartReader.app`，再校验应用标识、可执行文件和签名，但不会自动启动应用。可通过 `--install-dir <绝对路径>` 安装到其他目录。

## 本地桌面复测

以下复测使用项目已有的 Bun，并需 Python 3 生成合成论文；不需要真实厂商 API Key。

```bash
# 生成 4 份合成 PDF，其中 3 份内容唯一
python3 scripts/qa/create-papers.py /tmp/smartreader-qa-papers

# 在单独终端启动兼容 API 测试服务
bun scripts/qa/mock-ai.mjs

# 服务运行后，在另一终端验证无界面业务串联
bun scripts/qa/verify-workflow.ts /tmp/smartreader-qa-papers

# 构建独立 QA 标识的 macOS 应用包，隔离正式应用的数据目录
bunx tauri build --debug --bundles app --config '{"identifier":"com.smartreader.qa20261011","productName":"SmartReader QA"}'

# 用户明确启动 QA 应用
open "src-tauri/target/debug/bundle/macos/SmartReader QA.app"
```

`verify-workflow.ts` 使用真实 PDF.js、文献/AI 服务、加密及本机 HTTP，但存储是内存中的 `LibraryStorage`。它核对导入去重、分类、人工值、检索引用、加密和重建服务实例后的恢复；原生 SQLite/HTTP 另有 Rust 测试。这些结果不能替代真实桌面 UI 操作和应用退出后的重启验收。

知识库另有独立联合复测，无需启动应用：

```bash
bun scripts/qa/verify-knowledge.ts
```

脚本创建自己的临时 PDF 和 SQLite 文件，调用 Rust 测试桥中的实际原生存储、向量检索和 HTTP 传输，验证无关键词匹配问题的第 2 页语义命中、指定文件隔离、关闭连接后的持久化恢复、加密缓存清除、锁定/解锁、重建 AI 服务后完整云端索引复用、切回本地后的加密云向量清理，以及无文献时的直接对话。聊天、embedding 与 Milvus 使用本机协议夹具，请求经过原生端点白名单；脚本结束后关闭自己的服务并删除临时目录。它不证明真实阿里云、真实 Milvus 或 Tauri GUI 已通过验收。
