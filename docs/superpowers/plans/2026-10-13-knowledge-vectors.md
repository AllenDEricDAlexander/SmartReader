# AI 问答文件范围与向量知识库

## 需求与边界

修复问答无法添加本地文件、无法选择知识库范围的问题。根据用户确认，本地采用轻量向量实现，云端使用 Milvus，embedding 复用现有阿里云厂商配置并补充独立模型。沿用现有受管 PDF、全文索引、厂商凭据、引用跳页和文献加密服务。

本地 SQLite 是持久化来源，sqlite-vec 是当前请求范围的内存向量索引。Milvus 使用每次请求独立的临时集合，不增加文献同步。通过现有 Adapter 方式隔离本地原生命令与云端 REST 这一明确变化点，业务服务共用分块、缓存和引用校验；无需新增数据库进程或 Python 运行组件。

## 实施步骤

1. `ReaderApp`、`AiAssistant`：在问答页导入 PDF 并返回真实文献 ID，支持多选与明确范围；空选择、无文本、锁定及删除均显示可操作状态。
2. `embeddingsClient`、`AiSettings`、`AiService`：独立 embedding 模型和可选地址，沿用兼容 HTTP 的取消、超时和错误边界。聊天/embedding 地址改变时清除旧凭据。已知阿里云混合思考模型在非流式调用中明确关闭思考。
3. `knowledgeService`、`knowledgeStorage`、`knowledgeVectors`：逐页分块，内容/模型指纹缓存，建立与取消索引，所选范围语义检索和可验证引用。加密文献只在解锁会话缓存，不上传到 Milvus；向量生成和聊天的外部传输在界面与 README 中说明。
4. Rust `knowledge_vectors`、`library_storage`：加入静态 sqlite-vec、本地缓存读写与请求范围隔离。新增唯一 `008_knowledge_vectors.sql`，保留原迁移。加密/删除与公开缓存清理原子提交，迟到结果不得恢复私有持久化缓存。
5. 以组件/服务测试、Rust 原生测试、前端构建及真实 PDF + SQLite/sqlite-vec 联合脚本验证。HTTP 厂商和 Milvus 夹具与真实服务验收分别记录。不启动正式应用，不改用户正式数据库或凭据。

## 关键故障行为

embedding 响应需完整、有序、有限且维度一致；索引容量提前检查。访问代次或内容变化时取消或更新索引。云端地址变化清除会话令牌；取消或失败后仍尝试删除本次拥有的临时集合，清理失败明确返回错误。所选文件没有语义命中时不生成无来源回答。
