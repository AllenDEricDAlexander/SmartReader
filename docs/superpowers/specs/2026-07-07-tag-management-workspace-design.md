# SmartReader 标签管理工作台设计

## 背景

当前 SmartReader 侧边栏已有“标签管理”入口，但进入后的页面仍是旧式标签管理组件，视觉和功能都无法满足原型要求。目标是将标签管理完善为与原型图一致的完整工作台，并补齐页面内展示到的真实业务能力。

本设计以高保真 UI 和真实数据闭环为硬要求：页面中的统计、文献、分布、活动和整理建议均来自 SQLite 持久化层查询或正式活动日志，不使用前端 mock 数据，也不使用临时派生统计作为最终能力。

## 目标

1. 修复标签管理入口，进入完整标签管理工作台，不再出现空白或占位页面。
2. 按原型还原桌面端页面结构、视觉密度、色彩、卡片、表格、标签云、右侧详情栏和分页。
3. 补齐搜索、颜色筛选、排序、清除筛选、分页、选中详情、创建、编辑、删除和合并等交互。
4. 新增后端标签看板查询接口，统一返回页面所需完整真实数据模型。
5. 新增标签活动日志迁移，持久化记录标签相关操作，支撑真实“最近活动”。
6. 保持首页、阅读器、最近文件、收藏文件、批注管理、书签管理等既有行为不变。

## 非目标

1. 不引入新前端框架、图表库、状态管理库或 CSS 框架。
2. 不重构非标签相关页面。
3. 不修改既有 Flyway/SQLite migration 文件，只新增一个版本迁移。
4. 不使用 mock 数据填充页面。
5. 不自动启动项目运行；完成后由用户自行运行应用验收。

## 页面结构

标签管理页面继续运行在现有 SmartReader 主框架内，复用顶部栏和左侧导航。标签工作台本身分为中间主区和右侧详情栏。

### 中间主区

中间主区包含：

1. 页面标题“标签管理”。
2. 工具栏：搜索框、颜色筛选、排序下拉、清除筛选按钮、创建标签按钮。
3. 标签概览卡：全部标签、使用中的标签、总使用次数、孤立标签。
4. 标签云卡：按使用情况和颜色展示高频标签，样式贴近原型中的彩色 pill。
5. 标签表格：展示标签名称、使用次数、关联文献数、最近使用时间、描述、操作。
6. 分页区：总记录数、上一页、页码、下一页、每页条数。

### 右侧详情栏

右侧详情栏包含：

1. 标题“标签详情”和关闭按钮。
2. 当前标签名称、颜色圆点和编辑按钮。
3. 使用次数、关联文献数、最近使用、创建时间、描述。
4. 代表性文献列表，来自真实标签关联文档或标签关联批注所在文档。
5. 文件夹分布，按真实关联文档路径目录聚合。
6. 最近活动，来自标签活动日志。
7. 批量整理建议，来自后端基于真实标签数据计算的建议。

## 数据模型与后端能力

### 新增迁移

新增 `src-tauri/src/migrations/004_tag_activity_log.sql`，只创建标签活动日志表和索引。旧 migration 文件不修改。

活动日志表建议字段：

- `id`: 主键。
- `tag_id`: 当前标签 ID，可为空，用于记录删除后仍可保留事件。
- `tag_name`: 事件发生时的标签名称快照。
- `action`: 事件类型，例如 `create`、`rename`、`recolor`、`merge`、`delete`、`attach_document`、`detach_document`、`attach_annotation`、`detach_annotation`。
- `target_type`: 目标类型，例如 `tag`、`document`、`annotation`。
- `target_id`: 目标 ID 或文档 key。
- `target_label`: 目标展示名快照。
- `metadata_json`: 事件补充信息 JSON，例如 merge 源/目标、旧名称/新名称。
- `created_at`: 事件时间。

### 写入联动

以下命令在成功修改数据后写入活动日志：

1. `create_tag`
2. `rename_tag`
3. `delete_tag`
4. `merge_tags`
5. `attach_document_tag`
6. `detach_document_tag`
7. `attach_annotation_tag`
8. `detach_annotation_tag`

如未来增加颜色编辑能力，也将记录 `recolor`。

### 看板查询接口

新增 Tauri command，例如 `load_tag_dashboard`，由 Rust 持久化层统一查询并返回页面完整模型。

返回模型包含：

1. `overview`: 全部标签数、使用中标签数、总使用次数、孤立标签数。
2. `tags`: 表格行数据，包含 ID、名称、颜色、使用次数、关联文献数、最近使用时间、创建时间、更新时间、描述。
3. `cloud`: 标签云数据，包含权重、颜色和计数。
4. `details`: 每个标签的详情数据或当前选中标签详情。
5. `documents`: 当前标签代表性文献。
6. `folderDistribution`: 当前标签关联文件夹分布。
7. `activities`: 当前标签最近活动。
8. `recommendations`: 批量整理建议。

### 真实统计规则

1. 使用次数 = 真实 `document_tags` 数量 + 真实 `annotation_tags` 数量。
2. 使用中标签 = 使用次数大于 0 的标签。
3. 孤立标签 = 使用次数等于 0 的标签。
4. 关联文献数 = 当前标签直接关联文档数量 + 当前标签关联批注所在文档去重数量。
5. 最近使用时间 = 当前标签最近的活动日志时间；若没有活动日志，则使用 `tags.updated_at`。
6. 代表性文献 = 当前标签关联文档和关联批注所在文档，按最近打开、批注/标签关系时间排序。
7. 文件夹分布 = 当前标签关联文档路径的父目录聚合；无路径归入“未知位置”。
8. 最近活动 = `tag_activity_log` 中当前标签或标签名称快照相关事件，按时间倒序。
9. 批量整理建议 = 后端基于真实标签数据计算空标签、低使用标签、相似名称标签、长期未使用标签和可合并候选。

## 前端实现设计

### 组件边界

保留 `src/tags/TagManager.tsx` 作为标签管理入口，内部重构为工作台布局。建议拆分：

1. `TagDashboardToolbar`: 搜索、颜色筛选、排序、清除筛选、创建按钮。
2. `TagOverviewCards`: 标签概览统计。
3. `TagCloudPanel`: 标签云。
4. `TagTable`: 标签表格、行选择、行操作、分页。
5. `TagDetailsPanel`: 右侧详情栏。
6. `TagCreateEditDialog`: 创建和编辑标签。
7. `tagDashboardModels`: 前端响应类型与 UI 状态类型。

### 状态流

1. 页面进入时调用 `persistence.loadTagDashboard`。
2. 选中标签默认为使用次数最高或第一条标签。
3. 搜索、颜色筛选、排序和分页只影响前端当前列表视图，不改变后端数据。
4. 创建、编辑、删除、合并成功后重新加载 dashboard，保证所有统计来自后端真实结果。
5. 删除当前选中标签后切换到 dashboard 返回的下一个可选标签。
6. 后端请求失败时在页面内显示原型风格错误状态，并保留重试入口。

### 样式策略

1. 在 `src/app/styles.css` 增加标签工作台专属类名，避免影响其他页面。
2. 复用现有 CSS 变量，保持 SmartReader 整体一致性。
3. 按原型还原浅灰背景、白色卡片、细边框、圆角、主蓝按钮、彩色标签 pill、表格行高、右栏卡片密度和分页按钮。
4. 桌面优先，匹配原型宽屏布局；窄屏时右侧详情栏可下移，不能破坏桌面高保真。

## 交互设计

1. 搜索：支持按标签名称和描述搜索。
2. 颜色筛选：按真实标签颜色筛选。
3. 排序：支持使用次数、关联文献数、最近使用时间。
4. 清除筛选：恢复默认筛选和排序。
5. 创建标签：输入名称和颜色，调用 `create_tag`。
6. 编辑标签：支持重命名；如补充颜色更新接口，则支持颜色编辑并写入活动日志。
7. 删除标签：确认后调用 `delete_tag`，删除后刷新 dashboard。
8. 合并标签：选择目标标签后调用 `merge_tags`，成功后刷新 dashboard。
9. 标签云和表格行点击：切换右侧详情。
10. 代表性文献点击：如文件仍可打开，跳转到对应文档。
11. 整理建议点击：进入相应整理动作，例如合并候选或查看空标签。

## 设计模式考虑

本任务需要显式考虑设计模式，但不应过度工程化。

1. 不采用 Strategy、Factory、Decorator、Command 等重型模式，因为当前变化点明确，直接函数和组件边界更清晰。
2. 采用轻量 ViewModel/DTO 边界：后端 command 返回标签工作台 DTO，前端按该 DTO 渲染。
3. 采用 Facade 思路但不新增抽象层：`load_tag_dashboard` 作为页面级查询入口，封装多表聚合细节，避免前端多次请求和自行拼装真实统计。
4. 该选择解决的真实问题是“页面需要多块真实聚合数据”，而不是为了引入设计模式。
